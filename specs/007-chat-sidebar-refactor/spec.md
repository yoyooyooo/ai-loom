## User Scenarios & Testing _(mandatory)_

### User Story 1 - Chat 模块使用双栏（历史+消息），并在路由中保留上下文 (Priority: P1)

作为用户，我进入 Chat 模块时，可以在左侧第二栏看到会话历史列表，右侧第三栏看到当前会话的消息内容；当我从历史中选择一条会话时，右侧消息随之更新，地址栏携带我的会话上下文，刷新后仍停留在该会话。

**Why this priority**: 该能力是 Chat 的核心浏览与回溯路径，决定使用体验一致性与可分享性。

**Independent Test**: 仅实现 Chat 的历史与消息区域、以及带会话上下文的路由，即可独立测试并对用户交付价值（保留刷新状态）。

**Acceptance Scenarios**:

1. **Given** 进入 `/chat`，**When** 历史中选择一条会话，**Then** 右侧显示对应消息且地址栏带有会话上下文（例如 `/chat/:id`）。
2. **Given** 当前在 `/chat/:id`，**When** 刷新页面，**Then** 仍能看到该会话的消息内容而非空白。
3. **Given** 历史为空，**When** 进入 `/chat`，**Then** 显示空态占位且不阻塞其他操作。

---

### User Story 2 - Explore 模块保持原有两栏（文件树+编辑器/预览） (Priority: P1)

作为用户，我切换到 Explore 模块时，主区域仍为文件树 + 编辑器/预览的两栏布局，功能表现与改造前一致，不被 Chat 的双栏约束。

**Why this priority**: 确保 Explore 现有能力与用户工作流不受影响，降低改造风险。

**Independent Test**: 仅验证 Explore 保持两栏布局与交互，即可独立测试并确认不回退。

**Acceptance Scenarios**:

1. **Given** 进入 Explore，**When** 浏览文件树与打开文件，**Then** 编辑器/预览正常显示、可滚动，表现与改造前一致。

---

### User Story 3 - 顶层第一栏为 icon-only 窄条导航 (Priority: P2)

作为用户，我通过界面最左侧的窄条（仅图标）在 Chat 与 Explore 等大模块间切换；该窄条固定在全局左侧，主区域用于各大模块自有内容。

**Why this priority**: 统一导航形式，释放主区域空间，避免不必要的固定宽度占用。

**Independent Test**: 仅实现窄条导航与模块切换，即可独立验证布局与可达性。

**Acceptance Scenarios**:

1. **Given** 位于任一模块，**When** 点击窄条上的模块图标，**Then** 主区域切换至目标模块且窄条宽度不超过设计上限。

---

### Edge Cases

- 会话历史为空：显示统一空态，不影响主区域其他操作；不得因loading/占位导致列表项高度跳变。
- 无当前会话：Chat 第三栏显示空态与引导，或选择历史后进入消息视图。
- 大量会话/消息：滚动性能与独立滚动容器行为正常，无整体页面“卡死”。
- 模块未声明第二/第三栏：主区域自适应为单栏铺满，无残留不可见占位（例如隐藏 256px gap）。
- 授权/权限异常或数据读取失败：以用户可理解的提示呈现，不泄露技术细节；允许重试。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: Sidebar 改造仅作用于 Chat 模块主区域的两栏（第二栏：会话历史；第三栏：会话消息）。
- **FR-002**: Explore 保持原布局（文件树 + 编辑器/预览），功能与视觉对齐改造前方案。
- **FR-003**: 布局容器支持“每个大模块可选 0–2 个附加栏”，未声明时主区域单栏铺满，不产生隐藏固定宽度占位。
- **FR-004**: Chat 第二栏渲染“会话历史列表”，第三栏渲染“当前会话消息列表”；选择历史项后，右侧加载对应消息。
- **FR-005**: 地址栏需同步会话上下文并可刷新恢复当前会话（直链可分享）。[NEEDS CLARIFICATION: 路由是否采用 `/chat/:id`，以及 ID 的规范（如使用会话ID而非文件路径）？]
- **FR-006**: 顶层第一栏为 icon-only 窄条导航，不保留 256px 等固定宽度 gap。
- **FR-007**: 历史列表、消息列表、Explorer 文件树/编辑器均为可独立滚动容器，页面整体保持可滚动。
- **FR-008**: 加载与空态指示不应挤压列表项高度（避免高度突变）。[NEEDS CLARIFICATION: 是否移除“恢复中”文案并统一骨架/指示条样式？]
- **FR-009**: 不对 docs/specs/cc 下文件做任何删除或破坏性改动。
- **FR-010**: Explorer 右侧内容区照搬既有实现，仅在新布局容器中承载显示。

### Key Entities _(include if feature involves data)_

- **会话（Conversation）**: 标识一次对话的元信息（例如：id、标题、创建时间、最近活动时间、条目数）。用于列表展示与路由上下文携带。
- **消息（Message）**: 归属于会话的单条记录（例如：id、会话id、角色、时间、内容概览），用于第三栏消息视图的加载与展示。

### Dependencies & Assumptions

- 依赖：Explore 模块现有功能与样式可被新布局容器无缝承载；会话历史/消息数据来源稳定可用。
- 假设：路由层支持携带会话上下文的动态参数；加载/空态风格可以统一为不挤压高度的指示方案。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 从点击历史项到看到对应消息内容的可感知时间 ≤ 1 秒（P90）。
- **SC-002**: 在 `/chat/:上下文` 刷新后恢复当前会话的成功率 ≥ 99%。
- **SC-003**: 宽屏（≥1920px）下第一栏为 icon-only，导航条宽度 ≤ 64px；无额外不可见宽度导致主区域缩减。
- **SC-004**: 历史/消息/Explorer 文件树与编辑器均可独立滚动，不出现整体页面不可滚动的情况（人工验证通过）。
- **SC-005**: 模块未声明第二/第三栏时主区域铺满，布局切换时无明显闪烁或重排卡顿（可感延迟 < 100ms）。
- **SC-006**: 直链（带会话上下文）可分享并正确加载目标会话（成功率 ≥ 99%）。

### FR-level Acceptance（关键项）

- 针对 FR-005（路由与刷新恢复）：
  - 进入 `/chat/:id` 刷新后自动还原对应会话消息；错误 `id` 返回引导或空态（可重试）。
  - 从历史选择会话后，地址栏更新并可复制直链分享；粘贴直链可直接进入目标会话。
- 针对 FR-007（独立滚动）：
  - 历史、消息、Explorer 文件树与编辑器区域均在容器内可独立滚动，不影响主页面滚动行为。
- 针对 FR-008（加载/空态不挤压）：
  - 加载指示采用不改变列表项高度的占位/指示条；移除高度突变引起的跳动。
